Сертификат VPN / прокси

Настройка доверия Python без отключения TLS-проверки

← Вернуться в приложение

Почему появляется ошибка

Python не доверяет одному из сертификатов в TLS-цепочке соединения с GigaChat. Это может быть сертификат корпоративного VPN, HTTPS-прокси или антивирусной инспекции. Пока цепочка не доверена, запрос остановлен до передачи ключа авторизации.

Не отключайте проверку TLS через verify=False, CURL_CA_BUNDLE= или аналогичный обход: он делает соединение уязвимым для подмены.

Что запросить у администратора сети

  1. Корневой или промежуточный CA-сертификат, которым VPN/прокси подписывает HTTPS-трафик.
  2. Сертификат в PEM или Base-64 X.509 формате, обычно файл с расширением .pem или .crt.
  3. Отпечаток SHA-256 сертификата, сообщённый отдельно от файла, чтобы сверить подлинность.
  4. Подтверждение, что организация разрешает этому компьютеру обращаться к API GigaChat через данный VPN/прокси.

Не загружайте случайные CA-сертификаты с сайтов и не устанавливайте их без проверки владельца сети.

Подключение сертификата для backend

  1. Сохраните проверенный CA-файл, например C:\Med_centr\backend\certs\organization-proxy-ca.pem. Не добавляйте приватный ключ, если его отдельно не выдал администратор; для доверия нужен публичный сертификат CA.
  2. Откройте `backend\.env` и укажите полный путь:
SSL_CERT_FILE=C:\Med_centr\backend\certs\organization-proxy-ca.pem
  1. Полностью остановите backend и запустите `start.bat` заново, чтобы Python получил переменную окружения до запуска HTTPX.
  2. Нажмите генерацию СОПа. Если цепочка сертификатов принята, ошибка TLS исчезнет; при отказе учётных данных интерфейс отдельно сообщит HTTP 401.

Официальная документация

HTTPX: SSL certificates and verification

HTTPX использует системное хранилище сертификатов через `truststore`, когда пакет доступен, либо CA bundle из окружения. Для этой конфигурации можно указать проверенный CA-файл через SSL_CERT_FILE. Серверный сертификат по-прежнему проверяется.

Если после этого будет HTTP 401

TLS-соединение уже установлено, но GigaChat отклонил авторизацию. Проверьте в кабинете провайдера, что client ID и secret принадлежат одной паре, ключ не отозван/не истёк, scope соответствует типу доступа, а доступ к API активирован. Не отправляйте секреты в чат или скриншоты.

Проверку TLS отключать нельзя.
