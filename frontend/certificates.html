Сертификат Минцифры

Подключение корневого сертификата Минцифры для Python без отключения TLS-проверки

← Вернуться в приложение

Почему появляется ошибка

Python не доверяет одному из сертификатов в TLS-цепочке соединения с GigaChat. В российских корпоративных сетях это чаще всего корневой или промежуточный сертификат Минцифры, выдаваемый через локальный УЦ или VPN/прокси инфраструктуру. Пока цепочка не доверена, запрос останавливается до передачи ключа авторизации.

Не отключайте проверку TLS через verify=False, CURL_CA_BUNDLE= или аналогичный обход: это делает соединение уязвимым для подмены.

Что запросить у ИТ / администратора

  1. Корневой или промежуточный сертификат Минцифры / УЦ вашей организации, которым подписан HTTPS-трафик и работа с GigaChat.
  2. Файл в формате PEM или Base-64 X.509, обычно с расширением .pem или .crt.
  3. Отпечаток SHA-256 сертификата, чтобы сверить подлинность и исключить подмену.
  4. Подтверждение, что компьютер имеет доступ к API GigaChat и сертификат относится именно к вашей инфраструктуре Минцифры/УЦ.

Не загружайте случайные CA-файлы из интернета и не устанавливайте их без проверки владельца сети.

Подключение сертификата Минцифры для backend

  1. Сохраните проверенный CA-файл, например C:\Med_centr\backend\certs\mincifra-root-ca.pem. Для доверия нужен публичный сертификат CA, а не приватный ключ.
  2. Откройте backend\.env и укажите полный путь:
SSL_CERT_FILE=C:\Med_centr\backend\certs\mincifra-root-ca.pem
  1. Полностью остановите backend и запустите start.bat заново, чтобы Python получил переменную окружения до запуска HTTPX.
  2. Нажмите генерацию СОПа. Если цепочка корректна, ошибка TLS исчезнет; если только проблемы с токенами/доступом, интерфейс покажет отдельную ошибку авторизации HTTP 401.

Официальная документация

HTTPX: SSL certificates and verification

HTTPX использует системное хранилище сертификатов через truststore, когда пакет доступен, либо CA bundle из окружения. Для этой конфигурации можно указать проверенный корневой сертификат Минцифры через SSL_CERT_FILE. Серверный сертификат по-прежнему проверяется.

Если после этого будет HTTP 401

TLS-соединение установлено, но GigaChat отклонил авторизацию. Проверьте в кабинете провайдера, что client ID и secret принадлежат одной паре, ключ не отозван/не истёк, scope соответствует типу доступа, а доступ к API активирован. Не отправляйте секреты в чат или скриншоты.

Проверку TLS отключать нельзя.
